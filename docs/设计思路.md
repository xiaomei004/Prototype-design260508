**设计思路**
这个原型围绕文档里的核心价值展开：用“随手拍识别”把校园流浪动物从线下偶遇变成可查询、可维护、可追踪的数字档案。

整体采用移动端 H5 结构，因为该系统的主要使用场景是学生在校园中随时拍照、打卡、查看图鉴。页面使用底部四 Tab：`发现`、`随手拍`、`图鉴`、`我的`，对应文档中的发现广场、AI 识别、动物名录和个人中心。视觉上以橘黄色作为主色，配合绿色表示健康/已绝育，红色表示紧急救助，保持和需求文档中的 UI 规范一致。

实现上没有引入 Vue/Tailwind，而是做成纯静态 `HTML + CSS + JS`，这样可以直接打开 [index.html](/c:/Users/chen/Desktop/期末复习/大三下/软件项目管理/原型设计/index.html) 演示，不需要安装依赖或启动服务，更适合课堂展示。

**遇到的问题及解决方案**
一开始读取 md 文档时，终端出现了中文乱码。解决方式是重新用 `UTF-8` 编码读取文件，保证需求内容能够准确识别。

第二个问题是项目目录中没有现成前端工程。如果新建 Vue 工程，需要安装依赖，可能受网络和环境影响。为保证演示稳定，我选择实现为静态原型：用 [index.html](/c:/Users/chen/Desktop/期末复习/大三下/软件项目管理/原型设计/index.html) 承载结构，[styles.css](/c:/Users/chen/Desktop/期末复习/大三下/软件项目管理/原型设计/styles.css) 负责移动端视觉和动画，[app.js](/c:/Users/chen/Desktop/期末复习/大三下/软件项目管理/原型设计/app.js) 负责状态、筛选、弹窗和识别流程。

第三个问题是没有后端数据库。解决方案是在前端内置 Mock 数据，并使用 `localStorage` 保存新建档案。这样用户在“随手拍”中新建动物后，数据会实时追加到“图鉴”页面，模拟了前后端数据联动。

**核心交互流程**
核心流程是“随手拍 AI 识别”。用户进入 `随手拍` Tab 后，点击“点击拍照 / 上传”区域，页面会隐藏上传按钮，显示模拟动物预览图，并覆盖半透明扫描层。扫描线会上下移动，同时显示“AI 正在提取动物特征...”，用 `setTimeout` 模拟 2 秒识别耗时。

2 秒后系统通过 `Math.random()` 模拟识别结果分支。如果识别为老朋友，会弹出“匹配成功！匹配度 92%”，展示“大橘”的档案卡片，并提供“去打卡喂食”和“查看图鉴”操作。如果识别为新成员，会弹出建档表单，用户填写昵称、种类、发现位置和特征标签后，点击“生成新档案”，新动物会被加入全局动物列表并保存到 `localStorage`，随后自动跳转到“图鉴”页面展示结果。

这个流程覆盖了文档要求的完整闭环：`上传图片 -> AI 扫描动画 -> 匹配已有档案 / 新建档案 -> 图鉴实时更新`。
