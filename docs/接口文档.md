# 校园流浪动物管理系统接口文档

## 1. 文档说明

本文档用于约定前后端联调接口，适用于当前技术方案：

- 前端：`Vue 3 + Axios`
- 后端：`Spring Boot`
- 数据库：`MySQL`

接口统一前缀建议为：

`/api`

统一返回格式建议为：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

失败返回示例：

```json
{
  "code": 400,
  "message": "参数错误",
  "data": null
}
```

## 2. 认证说明

除注册、登录接口外，其余接口默认需要在请求头中携带 `token`：

```http
Authorization: Bearer <token>
```

## 3. 用户认证接口

### 3.1 用户注册

- 方法：`POST`
- 路径：`/api/auth/register`

请求参数：

```json
{
  "username": "student01",
  "password": "123456",
  "nickname": "李同学"
}
```

返回示例：

```json
{
  "code": 200,
  "message": "注册成功",
  "data": {
    "id": 2,
    "username": "student01",
    "nickname": "李同学",
    "role": "USER"
  }
}
```

## 4. 动物档案接口

### 4.1 获取动物列表

- 方法：`GET`
- 路径：`/api/animals`

查询参数：

- `keyword`：关键字，可按名称或地点搜索
- `species`：种类，例如 `猫`、`狗`
- `status`：状态，例如 `已绝育`、`健康`
- `pageNum`：页码
- `pageSize`：每页数量

请求示例：

```http
GET /api/animals?keyword=大橘&species=猫&pageNum=1&pageSize=10
```

返回示例：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "list": [
      {
        "id": 1,
        "name": "大橘",
        "species": "猫",
        "gender": "未知",
        "color": "橘色",
        "location": "北区食堂",
        "status": "已绝育",
        "features": "亲人,贪吃",
        "imageUrl": "/uploads/cat1.png",
        "auditStatus": "APPROVED",
        "createTime": "2026-05-20 10:00:00"
      }
    ],
    "total": 1,
    "pageNum": 1,
    "pageSize": 10
  }
}
```

- `type`：动态类型，可选 `feed`、`rescue`、`checkin`

- `pageSize`

      {
        "id": 1,
        "userId": 2,
        "nickname": "李同学",
        "animalId": 1,

        "content": "在北区食堂打卡投喂大橘，状态活跃，亲人。",

    "pageNum": 1,

## 6. 图片上传接口

### 6.1 上传图片

- 方法：`POST`
- 路径：`/api/upload`
- 类型：`multipart/form-data`

表单参数：

- `file`：上传文件

返回示例：

```json
{
  "code": 200,
  "message": "上传成功",
  "data": {
    "fileName": "animal-20260520.png",
    "url": "/uploads/animal-20260520.png"
  }
}
```

## 7. 随手拍识别接口

### 7.1 图片识别与匹配

- 方法：`POST`
- 路径：`/api/scan`

请求参数：

```json
{
  "imageUrl": "/uploads/animal-20260520.png"
}
```

返回示例一：匹配成功

```json
{
  "code": 200,
  "message": "识别成功",
  "data": {
    "resultType": "matched",
    "similarity": 92.0,
    "animal": {
      "id": 1,
      "name": "大橘",
      "species": "猫",
      "location": "北区食堂",
      "status": "已绝育",
      "features": "亲人,贪吃",
      "imageUrl": "/uploads/cat1.png"
    }
  }
}
```

返回示例二：未匹配到已有档案

```json
{
  "code": 200,
  "message": "发现新成员",
  "data": {
    "resultType": "new",
    "similarity": 38.5,
    "animal": null
  }
}
```

说明：
第一阶段后端可以先使用模拟逻辑，例如随机返回匹配结果或根据文件名规则返回结果，保证前后端流程先跑通。

## 10. 前后端联调建议

- 前端统一封装 `axios` 请求实例，自动携带 `token`。
- 后端统一返回 `code`、`message`、`data` 三个字段，避免联调时判断混乱。
- 图片上传与业务提交建议分两步执行：
  1. 先调 `/api/upload`
  2. 再把图片地址带入业务接口
- `动物状态`、`审核状态`、`动态类型` 建议在前后端统一枚举值，减少字段不一致问题。
