# 校园流浪动物管理系统开发文档

## 1. 项目概述

本项目拟建设一个面向校园场景的流浪动物管理系统，服务于普通学生、教职工、动保协会和后勤管理人员。系统围绕“发现、建档、跟踪、救助、维护”五个核心环节展开，目标是让校园内流浪动物的信息可记录、可查询、可追踪。

现阶段前端原型已经完成，后续开发将采用前后端分离架构，对原型进行工程化实现。

项目核心目标如下：

- 支持用户上传校园流浪动物照片并进行识别或建档
- 支持查看动物档案、动态记录和活动区域
- 支持管理员审核档案、维护状态和处理异常信息
- 为后续接入图像识别能力预留扩展接口

## 2. 产品定位与用户画像

### 2.1 核心价值

系统的核心价值可以概括为：

**让每一只流浪动物都有迹可循，让每一次救助都有档可查。**

### 2.2 典型用户

- 普通用户：学生或教职工，可进行随手拍上传、查看动物图鉴、发布投喂动态、提交认领或领养申请。
- 管理员：动保协会或后勤部门成员，可审核新建档案、更新动物健康状态、处理异常预警、维护救助流程。

### 2.3 典型使用场景

- 爱心学生在校园偶遇流浪动物后，希望快速识别身份、查看档案并记录投喂信息。
- 管理员希望通过统一平台维护动物状态、查看社区动态并处理紧急救助事件。

## 3. 技术选型

### 3.1 总体技术栈

- 前端：`Vue 3` + `Vite` + `Vue Router` + `Pinia` + `Axios`
- 后端：`Java` + `Spring Boot`
- 数据库：`MySQL`
- 接口风格：`RESTful API`
- 构建工具：前端使用 `npm`，后端使用 `Maven`

### 3.2 选型理由

选择 `Vue 3` 作为前端框架，原因在于其组件化能力强、开发效率高，适合将当前静态原型快速拆分成多个页面和组件。

选择 `Spring Boot` 作为后端框架，原因在于其生态成熟、适合构建课程项目，能够快速实现接口开发、权限管理、文件上传和数据库访问。

选择 `MySQL` 作为数据库，原因在于其稳定、常用、资料丰富，适合存储用户、动物档案、动态记录、扫描记录等结构化数据。

## 4. 系统架构设计

### 4.1 架构模式

系统采用前后端分离架构：

1. 前端负责页面展示、用户交互、状态管理和接口调用。
2. 后端负责业务逻辑、数据校验、权限控制、文件上传和数据库操作。
3. 数据库负责持久化存储业务数据。

### 4.2 架构示意

```text
Vue3 前端
  ↓ Axios 调用
Spring Boot 后端
  ↓
MySQL 数据库

文件上传
  ↓
本地 uploads 目录 / 静态资源访问
```

### 4.3 后续扩展

当前版本先完成基础业务闭环，图像识别能力在后续版本中接入。系统在设计上保留 `scan` 识别接口，后期可以接入目标检测模型或相似度匹配模型。

### 4.4 页面信息架构

系统前端采用移动端四个主页面的结构：

1. 发现广场：展示数据看板、紧急通知和社区动态流。
2. AI 随手拍：完成图片上传、扫描动画和识别结果分支。
3. 校园图鉴：以列表和地图热区形式展示动物档案。
4. 个人中心：展示个人资料、我的建档、我的打卡和消息设置。

## 9. 接口设计

### 9.1 用户认证接口

- `POST /api/auth/register`：用户注册
- `POST /api/auth/login`：用户登录
- `GET /api/user/me`：获取当前用户信息

### 9.2 动物档案接口

- `GET /api/animals`：获取动物列表
- `GET /api/animals/{id}`：获取动物详情
- `POST /api/animals`：新建动物档案
- `PUT /api/animals/{id}`：修改动物档案
- `DELETE /api/animals/{id}`：删除动物档案

### 9.3 动态模块接口

- `GET /api/posts`：获取动态列表
- `POST /api/posts`：发布动态

### 9.4 上传与识别接口

- `POST /api/upload`：上传图片
- `POST /api/scan`：图片识别与匹配

### 9.5 接口返回规范建议

统一返回格式建议如下：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

失败时返回：

```json
{
  "code": 500,
  "message": "error",
  "data": null
}
```

## 10. 核心业务流程

### 10.1 用户登录流程

1. 用户输入账号和密码。
2. 前端调用登录接口。
3. 后端校验用户信息。
4. 登录成功后返回 `token`。
5. 前端保存 `token` 并跳转到系统首页。

### 10.2 随手拍识别流程

1. 用户在前端上传动物图片。
2. 前端先调用上传接口，拿到图片地址。
3. 前端将图片地址提交给识别接口。
4. 后端执行匹配逻辑。
5. 如果匹配成功，则返回已有动物档案信息。
6. 如果匹配失败，则返回“新成员”结果，由前端跳转到新建档案页面。

### 10.3 新建档案流程

1. 用户填写动物名称、种类、位置、特征等信息。
2. 前端调用新建档案接口。
3. 后端校验参数并写入数据库。
4. 建档成功后返回档案数据。
5. 前端更新图鉴页面内容。

### 10.4 动态发布流程

1. 用户填写动态内容并上传图片。
2. 前端提交动态发布请求。
3. 后端保存动态记录。
4. 首页动态流展示新发布内容。

## 13. 风险与应对

### 13.1 风险点

- 前端从静态原型迁移到 `Vue 3` 需要一定重构成本
- 后端从零搭建接口较多，联调容易出现字段不一致问题
- 图像识别模型实现难度较高，可能影响整体进度

### 13.2 应对策略

- 先完成基础业务闭环，再优化功能细节
- 优先统一数据库字段和接口返回结构
- 识别模块先做模拟版本，保证系统可演示
